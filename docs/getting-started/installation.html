Installation

BitsyJS ships as one dependency-free ES module. Install it with a package manager, or import the browser build straight from a CDN and skip the toolchain.

Requirements#

BitsyJS ships as a single ES module with no runtime dependencies. It expects a modern browser with Proxy, WeakMap, fetch, DOMParser and <template>. There is no build step for consumers, but the page must be served over http or https if you use b-view fragments, because fetch cannot read file:// URLs.

CDN#

The quickest way to start is the browser build served by jsDelivr, with no install step. Keep the version in the URL so a new release cannot change your page without a deploy. The docs site publishes the pinned URL as . 

<script type="module">
    const bitsyCdn = "{cdn}";
    const { BitsyJS, signal } = await import(bitsyCdn);

    const count = signal(0);
    const bitsy = new BitsyJS({ data: { count } });
    await bitsy.run();
</script>

Use a static import when the URL is known up front; it avoids the extra request a dynamic import needs.

<script type="module">
    import { BitsyJS } from "{cdn}";

    const bitsy = new BitsyJS();
    await bitsy.run();
</script>

npm#

npm install @im4all/bitsy-js

The package exposes two entry points. The default export is the readable source module; /min is the bundled and minified browser build. 

// Readable ES module, best with a bundler or dev server
import { BitsyJS, computed, effect, signal } from "@im4all/bitsy-js";

The same module exports both the class and the reactivity primitives:

Export What it is
BitsyJS The view class. Construct it with settings and call run().
signal Creates a reactive value. Call it to read, set/update to write.
computed Creates a read-only value derived from other signals.
effect Runs a side effect now and again when the signals it reads change.
isSignal Returns true when a value is a signal created by this module.

Wire it up#

Construct the instance with the data the page needs, then run it once after the DOM is available.

<div b-data>
    <h1>{title}</h1>
    <p b-if="online">Online</p>
</div>

<script type="module">
    import { BitsyJS } from "./bitsy.min.js";

    const bitsy = new BitsyJS({
        data: {
            title: "Status",
            online: true,
        },
    });

    await bitsy.run();
</script>

A module script is deferred by default, so it runs after the document has been parsed. If the script is not a module, call run() after DOMContentLoaded. Calling run() twice is not supported; create a new instance only for markup that was not part of the first run.

Bundle size#

The published browser build is about 29.8 kB minified and 8.9 kB gzipped. The package has zero runtime dependencies. The readable module in lib/ is split into small files so bundlers can tree-shake what you do not import.

Pre-render static output#

The package includes a small Playwright-based CLI that opens each page, waits for the rendered event and writes the resulting HTML. It is useful when you want crawlers or first paint to see the rendered markup. 

bitsy-prerender --src=./site --dist=./dist --clean

It requires the optional playwright dependency and a Chromium install. See Lifecycle for the flags and the ready signal it waits on.

Content security policy#

Directive expressions are compiled with new Function, so a page that uses expressions needs a policy that allows evaluation, for example script-src 'self' 'unsafe-eval'. If your policy forbids unsafe-eval, BitsyJS cannot run expressions; do not add the exception unless you trust every directive and every rendered value on the page.

Installation does not make input safe. The library renders values as HTML and evaluates expressions. Read Security before accepting user-generated markup.
