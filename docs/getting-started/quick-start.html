Quick start

Start with markup the server would send, add the directives that describe how it changes, then call run() once. Everything on this page runs in your browser.

Render a page#

The fastest way to understand BitsyJS is to watch it run. The scoreboard below is real markup on this page: placeholders, a loop, a b-if, signal bindings and b-on click handlers. Press the buttons to change the data and only the affected text updates.

1. Write the markup#

Start with the markup the server would send. Directives are ordinary attributes, and placeholders are ordinary text. If the script never loads, the page still shows the original HTML. 

<div b-data>
    <h1>{title()}</h1>

    <p b-if="players().length === 0">No players yet.</p>

    <ul>
        <li b-for="player of players()">
            {player.name} - {player.score} points
            <button b-on:click="addPoint(player.id)">+1</button>
        </li>
    </ul>
</div>

The wrapping b-data element creates the scope. Even a bare b-data attribute is enough: text and attribute placeholders are only bound inside a scope, while directives such as b-for and b-if can also read global data directly.

2. Describe the data#

Pass plain values, signals and functions in the constructor. A signal is read by calling it, which is why the markup says {title()} and players(). 

import { BitsyJS, computed, signal } from "./bitsy.min.js";

const title = signal("Scoreboard");
const players = signal([
    { id: 1, name: "Alpha", score: 10 },
    { id: 2, name: "Beta", score: 7 },
]);

const total = computed(() => players().reduce((sum, player) => sum + player.score, 0));

const addPoint = (id) => {
    players.update((list) => list.map((player) => (player.id === id ? { ...player, score: player.score + 1 } : player)));
};

const bitsy = new BitsyJS({
    data: { title, players, total, addPoint },
});

await bitsy.run();

signal.set() replaces a value and signal.update() derives the next one. Return a new array or object instead of mutating in place, because the signal compares values by identity.

3. Call run()#

run() is asynchronous and works in a fixed order: load fragments, attach scopes, render bindings, unwrap containers, remove directive attributes, bind events and forms, then dispatch the rendered event. The report at the top of this page is filled by a ready() callback after that pass. 

bitsy.ready(() => {
    console.log("rendered");
});

await bitsy.run();
The attributes are gone after the run. Inspect the scoreboard above: it no longer contains b-data, b-for, b-if, b-js or b-on:*. What is left is plain HTML.

4. Add interactivity#

b-on:event runs JavaScript in the scope of the element. Inside a loop, the current item is in scope, so addPoint(player.id) knows which row was clicked. $event and $el are available for the DOM event and the element that owns the handler. 

<input
    type="text"
    value="{name()}"
    b-on:input="name.set($event.target.value)"
/>

<p>Hello, {name()}</p>

Inputs are a common source of reactive state. The next pages cover each feature in isolation, starting with data binding.
