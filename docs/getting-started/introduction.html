Introduction

BitsyJS adds interactivity to existing HTML. Use directives in your markup to bind data, repeat elements, load fragments, or handle events without a component compiler or a virtual DOM.

What it is#

BitsyJS reads directives from the DOM when you call run(). For example, b-for repeats a list item, and b-on:click handles a click. You can load BitsyJS as an ES module without a build step or runtime dependencies.

It works with HTML from a server-side app, a static site generator, or a hand-written page. Render essential content in the original HTML if it needs to be available without JavaScript.

  • Keep the HTML you already have. There is no separate template language.
  • Avoid a build step. Import from npm or a CDN and call run().
  • Stay declarative. Directives are ordinary attributes or custom tags.
  • Render once by default. Use signals where the page needs to respond to changes.
  • Reuse server partials. Inline them with b-view.
Not a framework replacement. BitsyJS is not a replacement for React, Vue or Svelte in highly interactive applications. It is for pages that are mostly rendered already.

Why it is created#

The world didn't need another JS library. I just wanted to include a damn HTML file.

Sometimes I just want to make a quick HTML page. Change a line, upload the file over FTP, done. Yes, FTP. I know what year it is. I got tired of running a build every time I touched a page. If all I did was fix a typo, I don't need my laptop or a build server to make an event out of it.

The first thing I wanted was to include one HTML file in another, like PHP's include. Plain HTML doesn't have that. Then I wanted to declare a JavaScript variable and use it in my markup, loop over a list, validate a form, and make an HTTP request. All small things. Somehow I kept ending up with either a full framework or three libraries in a trench coat.

There are other libraries that don't need a build step. Some felt more complicated than the page I was trying to make, and I often needed to add another library anyway. I still have a soft spot for jQuery. Being able to drop in a script and get on with it was genuinely cool.

I use modern frameworks too. They're great when I'm building an app. But for docs, a quick presentation, or a landing page, I wanted to start with HTML and keep it that way. So I built BitsyJS. Even in the AI era, I wrote the code by hand because I wanted to think through what actually needed to be there and leave the rest out. I want to be able to come back in six months and still know how it works.

When to use it#

BitsyJS works best when most of the page is already rendered and only a few areas need to respond to user actions or data changes.

Good fit

  • Server-rendered pages and admin screens
  • Static sites with interactive controls
  • Progressive enhancement on existing markup
  • Pages with a few dynamic sections, such as a filter or a form

Poor fit

  • Highly interactive applications
  • Teams that want a component compiler
  • Markup that only exists on the client
  • Apps that need a large ecosystem of plugins

The mental model#

Call run() once to apply directives to the existing DOM. After that pass, bindings that read signals update when those signals change. Bindings that read only plain values do not update on their own.

Try typing a name and toggling Signed in. The input updates a signal, and the checkbox switches which message is visible. The code after the live demo shows what the initial render can do with plain values instead of signals.

How a render runs#

The initial run() applies directives in this order:

  1. Fragments load. Each nested b-view URL resolves relative to the fragment that contains it.
  2. Scopes attach. Global data is the base, and each b-data adds its own keys.
  3. Bindings apply. Placeholders, b-for, b-if and b-js render.
  4. Unconditional <b-container> wrappers are replaced by their children.
  5. BitsyJS removes the b-data attributes.
  6. BitsyJS attaches event handlers and sets up form handling and validation.
  7. bitsy.rendered fires. Callbacks registered with ready() or on("rendered") run.

Register ready() before calling run(). It does not replay an event that already fired. See Lifecycle for details.

Directives at a glance#

Use the attributes and elements below to describe what BitsyJS should do with your markup.

Core directives and their syntax
Directive Syntax Purpose
b-data <div b-data> Creates a local scope for placeholders and nested directives.
b-for <li b-for="item of items"> Repeats the element for each item and exposes loop metadata.
b-if <p b-if="isReady"> Shows or hides an element with display: none.
b-js <span b-js="total()"> Evaluates an expression and writes the result as HTML.
b-on <button b-on:click="save()"> Runs JavaScript in the current scope when the specified DOM event fires.
b-view <b-view src="./card.html"> Fetches an HTML fragment and inserts it in place of the tag.
b-container <b-container> Groups markup and removes its wrapper unless the container has a condition.
data-b-* data-b-event, data-b-validate Declarative events, remote templates and form validation.

Data and scopes#

A b-data scope starts with the constructor's global data and overrides it with local keys. A nested b-data scope starts from the same global data, not from its parent's local keys.

  • b-for adds the item alias, _index, _isFirst and _isLast.
  • Inside a loop row, directives can read the current item and loop metadata.
  • Local objects replace global objects as a whole value. There is no deep merge.

Read the full rules in Scoping.

Signals#

Use signal(initialValue) for state that changes after run(), and computed(() => ...) for values derived from signals. Pass both in the constructor's data and call them as functions in bindings. 

import { BitsyJS, computed, signal } from "./bitsy.min.js";

const count = signal(0);
const doubled = computed(() => count() * 2);

const bitsy = new BitsyJS({ data: { count, doubled } });
await bitsy.run();

Events and forms#

b-on:event runs JavaScript in the current scope. $event is the DOM event, $el is the element that owns the handler, and the current loop item is in scope when there is one. Declarative data-b-event attributes cover the common click effects, and forms can validate and submit with fetch using the same attribute pattern. 

<form
    action="/signup"
    method="post"
    data-b-validate-form="true"
    data-b-form-ajax="true"
    data-b-form-ajax-target="#result"
>
    <input name="email" data-b-validate="required|email" />
    <small data-b-validate-message="email"></small>
    <button type="submit">Sign up</button>
</form>

See Event bindings, Forms and Validation.

Security#

Trust your expressions and HTML sources. BitsyJS evaluates directive expressions with new Function and can insert values, fragments, and remote responses as HTML. Never build expressions from untrusted input or insert untrusted input as raw HTML.

Read the full trust model in Security.
