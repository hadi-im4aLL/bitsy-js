Introduction

BitsyJS is a tiny view layer for HTML that is already on the page. It reads attributes, binds data, repeats blocks, shows and hides elements, loads fragments, wires events and validates forms, then removes the attributes it used.

What it is #

BitsyJS enhances existing HTML after the page loads. It reads directives from the DOM and fills in data, repeats blocks, shows or hides elements, loads fragments, wires events, fetches remote data and validates forms. There is no virtual DOM, component compiler, runtime dependency or build step for consumers.

It is built for HTML produced by server-side apps, static site generators or hand-written pages. The markup that reaches the browser is the markup the user reads, whether or not the script runs.

  • Keep the HTML you already have. There is no separate template language.
  • Avoid a build step. Import from npm or a CDN and call run().
  • Stay declarative. Directives are ordinary HTML attributes.
  • Render once by default. Use signals where the page needs to respond to changes.
  • Reuse server partials. Inline them with b-view.
  • Improve pages progressively. If JavaScript fails, the original markup remains.

Not a framework replacement. BitsyJS is not a replacement for React, Vue or Svelte in highly interactive applications. It is for pages that are mostly rendered already.

When to use it #

The library earns its place when the server already knows what the page should say. It works best on pages with a small number of interactive regions and a lot of static content.

Good fit

  • Server-rendered pages and admin screens
  • Static sites that need a little behaviour
  • Progressive enhancement on existing markup
  • Pages that render once and then settle

Poor fit

  • Highly interactive applications
  • Teams that want a component compiler
  • Markup that only exists on the client
  • Apps that need a large ecosystem of plugins

Install #

Install the package, then import the browser build. It is a single ES module.

Terminal 
npm install @im4all/bitsy-js
app.js 
import { BitsyJS } from "@im4all/bitsy-js";

const bitsy = new BitsyJS();
await bitsy.run();

The same build is published as dist/bitsy.min.js on jsDelivr and unpkg, so a module script can import it without a package manager.

First render #

Start with the markup the server would send. The placeholders and directives are already in the document; BitsyJS only fills them in.

index.html 
<div b-data>
  <h1>{title}</h1>

  <p b-if="isLoggedIn">Welcome back, {user.name}</p>
  <p b-if="!isLoggedIn">Please sign in.</p>

  <ul>
    <li b-for="player of players">
      {_index}: {player.name} - {player.score}
    </li>
  </ul>

  <button data-b-event="click" data-b-event-toggle-class="active">
    Toggle
  </button>
</div>
app.js 
import { BitsyJS } from "@im4all/bitsy-js";

const bitsy = new BitsyJS({
    data: {
        title: "Scoreboard",
        isLoggedIn: true,
        user: { name: "Ada" },
        players: [
            { name: "Alpha", score: 10 },
            { name: "Beta", score: 7 },
        ],
    },
});

bitsy.ready(() => console.log("rendered"));
await bitsy.run();

Inspect the page after run() resolves. The values are in place and the directive attributes are gone, so the DOM is plain HTML again.

How a render runs #

run() is asynchronous and always works in the same order. Each step finishes before the next one starts.

  1. Fragments load. b-view fetches partials, and nested paths resolve relative to the parent.
  2. Scopes attach. Global data is the base, and each b-data shallow-merges local keys over it.
  3. Bindings apply. Placeholders, b-for, b-if and b-js render against those scopes.
  4. Containers unwrap. b-container removes its own wrapper from the DOM.
  5. Directives are removed. The attributes that ran no longer exist on the page.
  6. Events and forms attach. b-on listeners and data-b-validate forms are wired.
  7. bitsy.rendered fires. Callbacks registered with ready() or on("rendered") run.

Listeners registered after the first render wait for the next one. If a fragment loads later, bindings inside it use the same global data and the nearest scope.

Directives #

Six directives cover rendering. Each one is an HTML attribute, and each one is removed once it has done its work.

Core directives, their purpose and their syntax
Directive Purpose
b-data="{ key: value }" Creates a local data scope. Placeholders use {path.to.value}.
b-for="item of items" Repeats an element for each item. Provides _index, _isFirst and _isLast.
b-if="expression" Shows or hides an element with display: none.
b-view src="./partial.html" Fetches and inlines an HTML fragment. Nested fragments are relative to their parent.
b-container Groups markup and removes the wrapper after rendering.
b-js="expression" Evaluates an expression and writes the result as HTML.

b-data values are JavaScript object literals, not strict JSON. Nested objects and arrays work, and strings starting with { or [ are parsed recursively. Values are rendered as HTML, and a missing or null value leaves the placeholder untouched.

Data scopes #

Global data from the constructor is the base for every scope. A b-data block shallow-merges its keys over that base, and nested blocks see the merged result.

index.html 
<div b-data="{ greeting: 'Hello' }">
  <p>{greeting}, {user.name}</p>
</div>
  • Global data is the base for every scope.
  • b-data shallow-merges local keys over global data.
  • b-for evaluates its list against global data and the nearest b-data scope.
  • b-if and b-js use the same scope. b-if also sees loop metadata, which takes precedence.

Signals #

Use signal(initialValue) for state that changes after run(), and computed(() => ...) for values derived from signals. Pass both in the constructor's data and call them as functions in bindings.

app.js 
import { BitsyJS, computed, signal } from "@im4all/bitsy-js";

const count = signal(0);
const doubled = computed(() => count() * 2);

const bitsy = new BitsyJS({
    data: { count, doubled },
});

await bitsy.run();
  • state.set(value) replaces a signal's value.
  • state.update(fn) derives the next value from the current one.
  • Text and attribute bindings, b-if and b-js update when the signals they read change.
  • A reactive loop such as b-for="item of items()" rebuilds its rows when the list changes.
  • effect(fn) runs a side effect immediately and again when its signals change. The returned function stops it.

For arrays and objects, return a new value rather than mutating in place. The signal only notifies when the value itself changes.

Events and forms #

b-on:event runs JavaScript in the current scope. $event is the DOM event, $el is the element that owns the handler, and the current loop item is in scope when there is one.

Declarative event attributes handle the common cases without a listener function. Forms can validate and submit with fetch using the same attribute pattern.

Declarative event attributes
Attribute Purpose
data-b-event="click" Binds any DOM event.
data-b-event-html, -text, -add-class, -remove-class, -toggle-class Applies an effect when the event fires.
data-b-event-revert="3s" Reverts supported effects after a delay.
data-b-event-remote="url" Fetches a URL and renders the response.
data-b-event-target="#id" Target element for rendered output.
data-b-event-indicator="is--loading" Class added to the target while a remote request runs.
signup.html 
<form
    action="/signup"
    method="post"
    data-b-validate-form="true"
    data-b-form-ajax="true"
    data-b-form-ajax-target="#result"
>
    <input name="email" data-b-validate="required|email" />
    <small data-b-validate-message="email"></small>
    <button type="submit">Sign up</button>
</form>

Available validation rules: required, email, min:n, max:n, length:n, number, int, float, bool, same:field, pattern:regex, date, date:Y-m-d, jsDate and time.

Invalid fields and their parents get the error class; valid fields get success. Both class names and messages can be changed through validatorConfig. AJAX forms support get, post, put, patch and delete.

Security #

Only evaluate what you trust. BitsyJS evaluates directive expressions such as b-data, b-if, b-js and b-on:* with new Function, and expressions can reach browser globals. HTML values, fragments and remote responses are inserted as markup. Never pass untrusted user input into them.
