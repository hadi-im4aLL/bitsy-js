Constructor and settings#

The public entry point is one class. new BitsyJS(settings) is valid without arguments; every setting has a default. Settings are copied into the instance when it is constructed, so decide the tags, the data and the validator options before you call run(). 

import { BitsyJS, signal } from "./bitsy.min.js";

const count = signal(0);

const bitsy = new BitsyJS({
    tags: { on: "x-on" },
    data: { count, title: "Counter" },
    validatorConfig: {
        classNames: { error: "is-invalid", success: "is-valid" },
        messages: { required: "Please fill this in" },
    },
});

await bitsy.run();
Constructor settings and their defaults
Setting Default Purpose
tags the twenty default names Directive names. Merged key by key over the defaults, so unspecified keys keep their default. See the table below and Custom tags.
data {} Base scope for every directive. Pass signals, computed values and functions here; a b-data literal cannot see module variables.
validatorConfig {} Validation classes and messages. See the notes below the tag table.

After construction, bitsy.settings holds the merged values the instance uses and bitsy.config holds the untouched defaults. Both are plain objects.

validatorConfig

  • classNames.error and classNames.success replace the error and success classes.
  • messages overrides one rule message at a time; rules you leave out keep their default text.
  • addClassToField and addClassToParent are read with an || true fallback, so passing false does not turn them off. Classes are always applied to the field and its parent.
  • Values are read when the instance is constructed, so a later mutation has no effect on that instance.

Methods#

Instance methods, signatures and return values
Method Returns Behaviour
run() Promise<void> Performs one render pass over the document in the fixed order described in Lifecycle. Supported once per instance; rejects on invalid b-data literals, failed fragment requests and exceptions thrown by rendered callbacks.
on(name, callback) this Registers a bus listener under bitsy.<name> and returns the instance for chaining. The callback receives the dispatch argument, which is undefined for rendered. The listener list is module-wide, not per instance.
ready(callback) undefined Shorthand for on("rendered", callback). It does not return the instance, so it cannot be chained.

These three methods are the intended API on the instance. The internal modules and the merged settings object also live on it, which is useful while inspecting a page but not a contract.

Module exports#

Named exports from the package entry point
Export Kind Purpose
BitsyJS class The renderer. Construct once per tag vocabulary and call run().
signal function Creates a reactive container. Call the result to read it.
computed function Creates a value derived from other signals.
effect function Runs a side effect now and again when the signals it reads change.
isSignal function Reports whether a value is a signal, including a computed value.

Signals, computed, effect and isSignal#

A signal is a function. Calling it reads the current value; when it is called inside an effect, that effect subscribes to it. Everything else is a property on the function object.

signal(initialValue)

Members of a signal
Member Signature Notes
read count() Returns the value and subscribes the active effect, if there is one.
peek count.peek() Returns the value without subscribing.
set count.set(next) Compares with Object.is, so an identical value does not notify. Notifies synchronously and returns the stored value.
update count.update(fn) Shorthand for set(fn(current)). Return a new value instead of mutating an object or array in place.
subscribe count.subscribe(cb) Adds a plain callback that receives the new value. Returns { unsubscribe }.
__isSignal count.__isSignal Always true. This is what isSignal checks, so bindings unwrap signals automatically.

computed(callback)

Members of a computed value
Member Signature Notes
read doubled() Returns the cached result and subscribes the active effect.
peek doubled.peek() Returns the cached result without subscribing.
subscribe doubled.subscribe(cb) Forwards to the signal that stores the result. Returns { unsubscribe }.
dispose doubled.dispose() Stops the internal effect. The value stops updating and keeps its last result.
__isSignal doubled.__isSignal Always true.

A computed value has no set and no update. It is eager: the callback runs once when the computed is created and again whenever a signal it read changes, even if nothing is currently reading the result.

effect(callback)

How an effect runs, tracks and stops
Aspect Behaviour
Return value A disposer function. Calling it removes the effect from every signal it subscribed to.
First run Immediately, before effect returns.
Re-run Synchronously, inside the set or update call that changed a dependency.
Tracking Signals read during the synchronous run only. Reads after an await are not tracked.
Dependencies Cleared before each run, so a branch that is no longer taken stops being a dependency.

isSignal(value)

Values isSignal recognises
Value Returns
The result of signal(...) or computed(...) true, because the function carries __isSignal === true.
Any other function, including DOM callbacks and plain helpers false.
Non-function values false.

Entry points, size and browser support#

Package entry points
Specifier File Use
@im4all/bitsy-js lib/bitsy.js Readable ES module source. Also the main field.
@im4all/bitsy-js/min dist/bitsy.min.js Browser build. Also the unpkg and jsdelivr fields.
@im4all/bitsy-js/package.json package.json Metadata, for tooling.

The built browser bundle is about 29.8 kB minified and 8.9 kB gzipped, with zero runtime dependencies. The documentation pages import the same bundle from assets/bitsy.min.js.

There is no transpiled build and no polyfill bundle. The library runs in current browsers and expects ES modules, Proxy, WeakMap, fetch, DOMParser, the template element, Range.createContextualFragment, class static fields, and async/await. It is a browser library: nodes default to document, so it is not a server-side renderer.

Errors and logging#

The library writes to the console with a tag prefix taken from the configured directive name, so a renamed directive reports its new name. Recoverable problems are logged and skipped; the failures that stop a render are listed under the table. It does not expose a logger setting.

Console messages produced by the library
Message When
[b-if] syntax error in "..." An expression cannot be compiled. Also what you see when a content security policy blocks new Function.
[b-js] runtime error in "..." An expression compiled but threw while running. Placeholders log nothing and keep their raw text.
Response status: 404 A fragment request answered with a non-ok status. The body is still inlined.
Error submitting form: ... An AJAX form submission failed. Submit controls are re-enabled afterwards.
No target element found for AJAX form submission. The form points at a response target that does not exist. Logged with console.warn.
  • A failed remote event request is not awaited by the event handler, so the browser reports an unhandled promise rejection and the loading indicator class is not removed.
  • An invalid b-data literal rejects run() instead of logging.
  • A thrown rendered callback rejects run() and prevents the DOM bitsy:rendered event.
  • For the full sequence, see Lifecycle errors.
