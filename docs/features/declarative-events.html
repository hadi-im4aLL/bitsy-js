Declarative events

Use data-b-event attributes to replace text or HTML, change a class, or fetch a URL without writing a JavaScript listener. Text, HTML, and class changes can revert after a delay.

The event attribute#

Set data-b-event to the event name and add data-b-event-* modifiers to specify what happens when it fires. 

<button type="button" data-b-event="click" data-b-event-text="Saved">
    Save
</button>

BitsyJS passes the event name directly to addEventListener. Use a standard event such as click, input, or change, or a custom event that the element receives.

Text and HTML#

data-b-event-text replaces textContent and data-b-event-html replaces innerHTML. Both remember the previous value, which is what revert restores later. 

<button type="button" data-b-event="click" data-b-event-text="Copied">Copy</button>

<button type="button" data-b-event="click" data-b-event-html="<strong>Saved</strong>">
    Save
</button>

The browser decodes entities such as &lt; in the attribute before BitsyJS reads it. Use only trusted markup with data-b-event-html; use data-b-event-text to display plain text.

Classes#

Three modifiers change classes: data-b-event-add-class, data-b-event-remove-class and data-b-event-toggle-class. Each one takes a single class name. 

<button type="button" data-b-event="click" data-b-event-add-class="is--loading">Start</button>

<button type="button" data-b-event="click" data-b-event-remove-class="is--loading">Stop</button>

<button type="button" data-b-event="click" data-b-event-toggle-class="is--loading">Toggle</button>

Each class modifier passes its value directly to classList. An empty value or a space-separated list throws when the event fires. Use a JavaScript listener to apply the same operation to multiple classes.

Revert#

data-b-event-revert turns a modifier into a temporary change. The value is read with parseFloat and treated as seconds, so 3, 3s and 1.5 all work. When the delay is over, each modifier undoes itself: text and HTML are put back, an added class is removed, a removed class is added again, and a toggled class is toggled once more. 

<button type="button"
    data-b-event="click"
    data-b-event-text="Saved"
    data-b-event-add-class="is--loading"
    data-b-event-revert="3s">
    Save
</button>

Each modifier schedules its own undo using the same delay. Class modifiers apply the inverse operation rather than restoring a snapshot: reverting an add removes the class even if it was already present. Revert has no effect on a fetch.

Several modifiers at once#

Modifiers on the same element run in attribute order. That order matters when they change the same content or class.

<!-- textContent is written last, so the HTML is replaced by plain text -->
<button type="button"
    data-b-event="click"
    data-b-event-html="<strong>Bold</strong>"
    data-b-event-text="Plain">
    Both
</button>

<!-- the class is added and then removed again, so nothing visible happens -->
<button type="button"
    data-b-event="click"
    data-b-event-add-class="is--loading"
    data-b-event-remove-class="is--loading">
    Add then remove
</button>

Reverse the two class attributes in the second example to leave the class on the element. Reverts also run in attribute order, not in reverse order.

Confirm and remote actions#

data-b-event-confirm passes its message to window.confirm before the fetch. If the user cancels, BitsyJS skips the request but still applies any text, HTML, or class modifiers on the element. 

<button type="button"
    data-b-event="click"
    data-b-event-remote="https://jsonplaceholder.typicode.com/users"
    data-b-event-target="#user-list"
    data-b-event-indicator="is--loading"
    data-b-event-confirm="Load the user list?">
    Load users
</button>

data-b-event-remote sets the URL and data-b-event-target selects where to render the response. Set the request method with data-b-event-remote-method and provide a JSON body for non-GET requests with data-b-event-remote-payload. JSON payloads are sent with Content-Type: application/json. data-b-event-indicator sets the loading class on the target, or on the trigger if no target matches. See Remote data and templates for response rendering.

What the attributes cannot do#

  • One event per element. data-b-event holds a single event name, so a button cannot listen for both click and input.
  • Values are literal strings. They are not evaluated and no page data is interpolated into them, so the text you write in the attribute is the text that lands on the page.
  • Modifiers act on the element that carries them. Only the remote action takes a data-b-event-target; text, HTML and class changes always land on the trigger.
  • Listeners are attached once, during run(), to the elements that exist at that moment. Markup added later is not wired.
  • Requests are not debounced or queued. Each event that triggers a fetch starts its own request after any confirmation.
  • The data-b-event attributes stay in the DOM after run(), unlike b-on attributes.
