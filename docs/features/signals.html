Signals

Use signal() for state, computed() for derived values, and effect() to run code when the signals it reads change. BitsyJS bindings update when their signals change.

Creating a signal#

Call a signal to read its value. Use set(value) to replace it or update(fn) to derive the next value from the current one. 

import { BitsyJS, signal } from "./bitsy.min.js";

const count = signal(0);

count();            // 0, and this read is tracked inside an effect
count.set(5);       // write a value
count.update(n => n + 1); // 6, the callback receives the current value

signal(initial) accepts any value, including arrays, objects and functions. To distinguish a signal from an ordinary function, use isSignal(value).

Reading, writing and identity#

set(value) compares the new and current values with Object.is. If they match, it does not notify subscribers or update bindings. 

const status = signal("idle");

status.set("idle");    // same string, no notification
status.set("running"); // different, every reader is notified

const todos = signal([{ text: "one" }]);

todos.peek().push({ text: "two" });
todos.set(todos.peek());        // same array reference, ignored

todos.set([...todos.peek(), { text: "two" }]); // new array, re-renders

Mutating an array or object in place changes its contents but does not notify readers, even if you pass the same reference to set(). To notify readers, create a new array or object with spread, map() or filter().

peek() reads the current value without tracking a dependency. subscribe(callback) calls the callback with each new value and returns { unsubscribe }. Notifications are synchronous, so subscribers and bindings run before set() returns.

Computed values#

computed(fn) derives a value from other signals and exposes it as a read-only signal. It is callable, and it has peek, subscribe and dispose, but no set or update. 

const count = signal(2);
const doubled = computed(() => count() * 2);

doubled();          // 4
count.set(3);
doubled();          // 6
doubled.peek();     // 6, no subscription

doubled.subscribe((value) => console.log("doubled", value));
doubled.dispose();  // stop recomputing, the last value stays readable

A computed recalculates when a signal read on its last run changes. It notifies its readers only if the result changes according to Object.is. Call dispose() to stop recalculation; the last value remains readable.

Effects and cleanup#

effect(fn) runs fn immediately, then again whenever a signal that the last run read changes. It returns a disposer. 

const stop = effect(() => {
    console.log("count is", count());
});

count.set(1); // logs again
stop();       // no further runs
count.set(2); // silent

An effect tracks only the signals it reads on its latest run. In this example, changes to rows() do not rerun the effect when enabled() is false. 

effect(() => {
    if (enabled()) {
        render(rows()); // rows() is tracked only while enabled() is true
    }
});

Keep the function returned by effect() and call it when you no longer need the effect. BitsyJS disposes each removed row's binding effects when a loop rebuilds.

Which bindings are reactive#

These bindings update when a signal they track changes. Event handlers run on events, not on signal writes.

Directive Reactive What happens on a write
Text placeholder {count()} Yes, one effect per placeholder Only that placeholder is rewritten
Attribute placeholder class="{state()}" Yes, one effect per attribute The whole attribute value is rebuilt
b-if Yes BitsyJS toggles the rendered element's CSS display value
b-js Yes The element's HTML is replaced with the new result
b-for Yes The entire list is cleared and every row rebuilt
b-on:click No The listener runs on a click and can read or write signals

Bindings read a signal the same way plain code does: call it. A signal returned from an expression is called for you, so {count} also renders the current value, but {count()} is the clear form and matches {doubled()} for computed values.

When a tracked signal changes, b-for replaces every row and binds the new elements and listeners. Store row state in your data if it needs to survive a rebuild.

Signals come through the constructor#

A b-data attribute cannot read module variables or constructor data. If the attribute refers to an unavailable variable, run() rejects. 

<!-- run() rejects with "Invalid data string" -->
<div b-data="{ count }">{count()}</div>

<!-- self-contained literals are fine -->
<div b-data="{ step: 1 + 1, label: 'draft' }">{step}</div>

Pass module signals, functions and computed values in the constructor's data option. Read them from placeholders and directives on the page, not from the b-data attribute itself. 

const bitsy = new BitsyJS({
    data: { count, doubled, todos, addTodo, removeTodo },
});

await bitsy.run();

    import { BitsyJS, computed, effect, isSignal, signal } from "./bitsy.min.js";

const count = signal(0);
const doubled = computed(() => count() * 2);

const draft = signal("");
const todos = signal([{ id: 1, text: "Read the signals page" }]);

let nextId = 2;
let logger = null;

const pushLog = (text) => {
    const list = document.querySelector("#signal-effect-log");
    const item = document.createElement("li");

    item.textContent = text;
    list.appendChild(item);

    while (list.children.length > 5) {
        list.removeChild(list.firstElementChild);
    }
};

const watchCount = () => {
    if (!logger) {
        logger = effect(() => pushLog("count is " + count()));
    }
};

const pauseCount = () => {
    if (logger) {
        logger();
        logger = null;
        pushLog("effect disposed, further writes are silent");
    }
};

const addTodo = (event) => {
    event.preventDefault();

    const text = draft().trim();

    if (!text) {
        return;
    }

    todos.update((list) => [...list, { id: nextId++, text }]);
    draft.set("");
};

const removeTodo = (id) => {
    todos.update((list) => list.filter((todo) => todo.id !== id));
};

watchCount();

const bitsy = new BitsyJS({
    data: { count, doubled, draft, todos, isSignal, addTodo, removeTodo, watchCount, pauseCount },
});

await bitsy.run();

    Writing a good update#

    Keep one source of truth and derive related values from it. In the demo, the counter, the computed double and the squared expression all use the same signal.

    Build a new value and set it once. BitsyJS does not batch writes, so multiple distinct writes in one handler can update the same binding more than once. Use peek() when a read inside an effect should not become a dependency.
