Conditionals

b-if evaluates an expression and hides the element with display: none when the result is falsy. It does not remove the element from the DOM.

How b-if decides#

b-if evaluates its attribute as a JavaScript expression and uses the ordinary truthiness of the result. false, 0, "", null, undefined and NaN hide the element; every other value shows it. The attribute does not need a big expression, and a bare identifier such as b-if="isLoggedIn" is enough. 

<p b-if="isLoggedIn">Welcome back</p>
<p b-if="!isLoggedIn">Please sign in</p>

<p b-if="role === 'admin' && score > 80">Admin with a high score</p>
<p b-if="attempts">There is at least one attempt</p>

The expression is evaluated in the element's scope: global data, the nearest b-data element and, inside a loop, the row scope. Missing names resolve to undefined, so a typo hides the element instead of throwing. Check Scoping for the exact rules.

Hiding is not removing#

A false condition sets display: none on the element. The element stays in the document, keeps its children, its listeners and its ids, and is still reachable with document.getElementById. Nothing is removed and nothing is re-created when the condition flips.

A true condition restores the inline display value the element had before run(). If the element had no inline display, the inline style is cleared and the browser default or a class rule applies again. An element that starts with style="display: none" is treated the same way: showing it clears the inline style instead of restoring none. That is why a badge keeps inline-flex from its class after a toggle, and why an element with style="display: inline-block" keeps that value.

Expressions and truthiness#

Any expression is allowed, including comparisons, boolean operators, arithmetic and calls into Math. A number is truthy unless it is zero, so a counter is a valid condition without an explicit comparison.

Expression set b-if

role is admin and score is above 80

plan is pro or score is above 90

role is not admin

attempts is truthy, so at least one attempt exists

attempts is falsy, and zero counts as falsy

NaN is always falsy, so this line never shows

Two of these six expressions are true with the starting data. Add an attempt or raise the score and the visible set changes.

Keep conditions small and readable. A long expression is a signal waiting to be written: derive the boolean in a computed, put it in the constructor data, and let b-if read the name.

Signals re-evaluate conditions#

Each condition runs inside an effect. When a signal the expression reads changes, that condition alone is re-evaluated and the element is shown or hidden again. A condition that reads no signals is evaluated once and then left alone. 

const expanded = signal(false);
const bitsy = new BitsyJS({ data: { expanded } });
await bitsy.run();
<button b-on:click="expanded.update(v => !v)">Toggle</button>
<div b-if="expanded()">Only in the DOM once, visible when expanded is true.</div>

Because the element is hidden rather than destroyed, content inside a hidden branch is not re-fetched, re-parsed or rebuilt when it becomes visible again. That makes b-if a cheap way to stage markup that already exists.

The nearest scope wins#

A condition reads the nearest b-data element and global data, with local keys winning. Two sibling scopes therefore evaluate the same expression differently, and neither scope can see the other.

The scope an element carries also applies to a condition on that same element, so a b-if beside a b-data attribute can read the local keys directly.

Conditions inside a loop#

Rows get the item alias plus _index, _isFirst and _isLast, so conditions can mark, filter and alternate rows without extra data. A hidden row takes no space on the page, but the element is still in the document.

Row conditions b-if and b-for
  • {job.name} first last even enabled disabled 
<li b-for="job of jobs">
    <span>{job.name}</span>
    <span b-if="job.enabled">enabled</span>
    <span b-if="!job.enabled">disabled</span>
    <span b-if="_index % 2 === 0">even row</span>
</li>

Conditions are processed per row after the row scope exists, which is why job.enabled and _index resolve inside a clone. See Loops for the rest of the row scope.

A conditional container becomes a span#

<b-container> normally unwraps into its children. With a b-if on the same tag it cannot, because hiding needs an element to hide. The tag is replaced by a <span style="display: inline-block"> that keeps the original attributes and children, and the wrapper stays in the document.

Conditional container b-container and b-if
first child second child

The pills above stay inside the wrapper instead of becoming direct children of the stack. 

<b-container b-if="groupOpen()">
    <span>first child</span>
    <span>second child</span>
</b-container>

<!-- after run(): -->
<span style="display: inline-block">
    <span>first child</span>
    <span>second child</span>
</span>

Use this when the group needs its own visibility switch. When the children should also become direct children of the parent, put b-if on each child instead and leave the container unconditional.

Rules to remember#

  • b-if hides with display: none; it never removes the element or its children.
  • A truthy result restores the original inline display, then the class and browser defaults take over.
  • Conditions are re-evaluated only for the signals their expression reads.
  • Conditions read global data, the nearest b-data scope and, inside a loop, the row scope.
  • A missing value is undefined, which hides the element instead of raising an error.
  • b-if on a <b-container> keeps a <span> wrapper; the tag is never unwrapped.
  • The attribute is removed after run(), so hidden elements can be found by id or class, not by b-if.
