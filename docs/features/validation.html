Validation

Validation rules live on the field as a pipe-separated list. On submit the form checks every rule, writes messages into the matching slots and adds error or success classes.

Rules live on the fields#

A field is validated only when it carries data-b-validate. The value is a pipe separated list of rules, and a rule that needs a parameter takes it after a colon: required|email|min:5. The form opts in with data-b-validate-form="true", and that value must be exactly true. 

<form action="/signup" method="post" data-b-validate-form="true">
    <div class="form-field">
        <label class="form-label" for="email">Email</label>
        <input class="form-input" id="email" name="email" data-b-validate="required|email" />
        <small class="form-text" data-b-validate-message="email"></small>
    </div>

    <button class="button button-primary" type="submit">Sign up</button>
</form>

Every rule for a field runs, in the order you wrote them, and each failure is collected into a list of messages. Rules that do not exist are ignored silently, and every rule except required returns early on an empty value, so required|email on an empty input reports only the required error.

    Rule reference#

    Validation rules, what each one checks and the message key it reads
    Rule What it checks Message key
    required The value is not empty. A checkbox must be checked, and a radio group needs one checked member. required
    email The trimmed value matches /^[^\s@]+@[^\s@]+\.[^\s@]+$/: one at sign, no spaces, and a dot in the domain. email
    min:5 String length is at least the number. It is not a numeric comparison. min
    max:5 String length is at most the number. max
    length:5 String length is exactly the number. length
    pattern:regex new RegExp(rest).test(value). The pattern is not anchored, so add ^ and $ for the whole value. pattern
    number Number.isFinite(Number(value)), so 42.5 and 7 pass. number
    int A finite number with no fractional part. int
    float A finite number. It does not require a decimal point, so 7 passes as well. float
    bool One of true, false, 1, 0, yes, no, on or off, case insensitive. Checkboxes and radios always pass. bool
    same:field The value is identical to the value of the field with that name in the same form. Comparison is a raw string comparison. same
    date Strict YYYY-MM-DD and a real calendar date. date:d/m/Y, date:m/d/Y, date:d.m.Y and other orders of the same three tokens work too. date
    jsDate Date.parse does not return NaN, so it follows the browser's date parsing instead of a fixed shape. jsDate
    time HH:mm in 24 hour form, or h:mm am and h:mm pm. time

    Message text: override any message key

    • date uses the three tokens Y, m and d; every other character in the parameter is matched literally, so d/m/Y and d.m.Y are just separators. Month and day accept one or two digits, and the day is checked against the real month length.
    • A rule that takes a parameter is skipped when the parameter is missing or 0, because the parsed value is checked for truthiness before the rule runs.
    • A parameter is split on colons, so a regular expression that contains a colon is truncated at it. Keep pattern expressions colon free, or check that value in your own code.
    • Rules are collected by name, so writing the same rule twice (min:3|min:8) keeps the last parameter instead of checking both.
    • Three keys have message text but no implementation in this version: url, requiredIf and datetime. They are not listed above because they never fail a field.

    Where messages appear#

    Messages are not generated next to the field. An element with data-b-validate-message inside the same form receives them, and the attribute value must match the field's name. When several rules fail, their messages are joined with a comma and a space. 

    <input class="form-input" name="password" type="password" data-b-validate="required|min:8" />
<small class="form-text" data-b-validate-message="password"></small>

    A valid field clears its slot back to an empty string, so the same element serves both states. To replace every message for one field with a single sentence, put data-b-validate-error-message on the field itself: the text is used instead of the joined rule messages. 

    <input
    class="form-input"
    name="password_confirm"
    type="password"
    data-b-validate="required|same:password"
    data-b-validate-error-message="The two passwords are not the same" />

<small class="form-text" data-b-validate-message="password_confirm"></small>

    Without a message slot the field is still validated and still gets its classes; only the text has nowhere to go.

    Error and success classes#

    A field that fails any rule gets the class error and loses success; a field that passes every rule gets success and loses error. The field's parent element receives the same class, so a wrapper such as .form-field can style the label and the helper text together. Fields without a data-b-validate attribute are never touched.

    The names are configurable through validatorConfig.classNames. The two switches addClassToField and addClassToParent exist in the config but are merged with || true, so passing false does not turn either off in this version.

    Configuring the text#

    The default messages live in the validator config. Pass validatorConfig to the constructor and override only the keys you want to change; the rest keep their defaults. 

    import { BitsyJS } from "@im4all/bitsy-js";

const bitsy = new BitsyJS({
    validatorConfig: {
        classNames: {
            error: "has-error",
            success: "has-success",
        },
        messages: {
            required: "This field cannot be empty",
            min: "Use at least {min} characters",
            max: "Use at most {max} characters",
            length: "Use exactly {length} characters",
            same: "This does not match {field}",
        },
    },
});

await bitsy.run();

    Four placeholders are substituted in the message text: {min}, {max}, {length} and {field}. Any other braces stay as written. The default min, max, length and same messages already use them.

    Validation runs on submit only#

    There is no live validation. BitsyJS attaches one submit listener per form during run() and does nothing while a field is edited, so a field keeps its error class until the next submit even after it has been corrected.

    • An invalid form cancels the submit event: nothing is sent and the page stays where it is.
    • A valid form continues into the AJAX handler when data-b-form-ajax="true" is present.
    • A valid form without the AJAX attribute is handed back to the browser with requestSubmit() and submits natively, as described on Forms.
    • A form added to the page after run() is not wired, and the validation attributes stay in the DOM.

    Checkboxes and radios#

    required understands both input types. A checkbox must have checked set, and a radio looks up the whole group by name in the form, so any checked member satisfies every radio of that group. 

    <input type="checkbox" name="terms" id="terms" data-b-validate="required" />
<small class="form-text" data-b-validate-message="terms"></small>

<input type="radio" name="plan" value="monthly" data-b-validate="required" />
<input type="radio" name="plan" value="yearly" data-b-validate="required" />
<small class="form-text" data-b-validate-message="plan"></small>

    A group also means a group of classes: every radio that carries the rule gets the error or success class, and because they share a name they share one message slot. The bool rule is the other exception to the text based checks: checkboxes and radios always pass it, because their value is not what the user chose.
