Event bindings

Use b-on:event to run JavaScript when an element receives a DOM event. The handler can access scoped data, the event as $event, and the bound element as $el.

The b-on syntax#

b-on:event="statement" attaches a DOM listener. The text after the colon is the event name, used as written in addEventListener, and the attribute value is JavaScript that runs with the element's scope. 

<button type="button" b-on:click="count.update(n => n + 1)">+1</button>

<input type="text" value="{draft()}" b-on:input="draft.set($event.target.value)">

<form b-on:submit="$event.preventDefault(); save()">
    <button type="submit">Save</button>
</form>

Use one attribute per event. An element can listen for several events, such as click, mouseenter, and mouseleave. 

<button type="button"
    b-on:click="save()"
    b-on:mouseenter="hovered.set(true)"
    b-on:mouseleave="hovered.set(false)">
    Save
</button>

When BitsyJS binds an element, it removes the b-on:* attributes and leaves the listeners attached. A binding with no event name or no code is removed without attaching a listener.

Statement semantics#

The value is compiled as a function body, not as an expression. Several statements, if blocks and local variables all work, and the result of the last statement is ignored. 

<button type="button" b-on:click="const next = count() + 1; count.set(next); report.set('set ' + next)">
    Increment and report
</button>

BitsyJS compiles the handler on first use. The function body is not async, so top-level await is a syntax error. BitsyJS logs syntax errors as [b-on] syntax error in "..." and catches synchronous errors as [b-on] runtime error in "...".

There are no modifiers and no listener options. b-on:click.once listens for an event literally named click.once, not a regular click. To use once, capture, or passive, attach the listener with addEventListener.

this inside the statement is the scope object, not the element. Use $el whenever the element itself is needed.

Scope of a listener#

A listener runs with the scope of its element: global data, plus the nearest b-data keys, plus the loop alias and metadata when the element is inside a b-for. That is why a row button can call a function with its own item. 

<li b-for="step of steps()">
    <span>{step.label}</span>
    <button type="button" b-on:click="toggleStep(step.id); report.set('row ' + (_index + 1))">
        Toggle
    </button>
</li>

BitsyJS captures scope values when it attaches the listener. A captured signal still returns its current value when called. When a loop rebuilds, BitsyJS removes the old listeners and binds the new rows with their own aliases and metadata.

The event object#

$event is the DOM event and $el is the element that carries the attribute. Both are injected on dispatch and shadow any data key with the same name. 

<div b-on:click="report.set('target ' + $event.target.tagName + ', element ' + $el.tagName)">
    <span>Click the label</span>
</div>

$event.target can be a descendant of $el. In this example, clicking the label reports the span as the target and the div as the bound element.

b-on does not cancel browser defaults or stop propagation. Call $event.preventDefault() to cancel a form submission, or $event.stopPropagation() to stop a bubbling click from reaching parent elements. 

<form b-on:submit="$event.preventDefault(); submitForm($event)">
    <input type="text" b-on:input="draft.set($event.target.value)">
    <button type="submit">Send</button>
</form>

Any DOM event#

The name is passed straight to addEventListener, so every DOM event works: click, dblclick, input, change, focus, blur, keydown, keyup, mouseenter, mouseleave, submit, copy, dragstart and the rest. A custom event dispatched on the element works the same way, for example b-on:team-updated.

For text fields, use input to react to value edits, including paste, and change to react when a changed field loses focus. Use keydown when you need the key rather than the new value.

Listener lifecycle#

During run(), BitsyJS scans the document for b-on attributes after processing fragments, bindings, directives, and containers.

  • Wait for run() to resolve before relying on the listeners.
  • A <b-container> wrapper is removed, so put b-on on a child that stays in the DOM.
  • BitsyJS does not automatically bind b-on attributes in markup inserted after run(), including remote responses and data-b-event-html content.

b-for can bind its own rebuilt rows after the initial scan. For markup you insert yourself, use addEventListener directly or handle bubbling events on a parent that stays in the DOM.

    Rules of thumb#

    Keep inline handlers short. Increment a counter or cancel a submit in the attribute, but move longer logic to a function exposed through the data object, such as b-on:click="removeTodo(todo.id)".

    Bind directly to a control when the handler needs that control as $el. If several controls share a handler for a bubbling event, bind to their parent and use $event.target to identify the control.
