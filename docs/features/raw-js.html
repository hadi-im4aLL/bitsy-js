Raw JavaScript

b-js evaluates a JavaScript expression in the current scope and writes the result into the element as HTML. It is the directive for values that are computed rather than looked up.

An expression becomes HTML#

b-js evaluates its attribute as a JavaScript expression in the element's scope and assigns the result to the element's innerHTML. The attribute value is the whole expression. 

<span b-js="count * 2"></span>
<span b-js="price.toFixed(2)"></span>
<span b-js="new Date().toLocaleDateString()"></span>

The result is assigned, not appended, so the element's content is whatever the last evaluation returned. A number or a boolean is coerced by the DOM, which means 0 renders as 0 and false renders as false. An object is coerced the same way and appears as [object Object], so return a string when you need something readable.

Use it for values that are computed rather than looked up. When you only need a path from the scope, a placeholder such as {user.name} is shorter and keeps the rest of the markup intact.

Building HTML strings#

The result is written as markup, not text, so a string containing tags creates real elements. That is what makes list rows, badges and small tables possible from a single expression. 

<div b-js="'<strong>' + count + '</strong> rows ready'"></div>
<div b-js="'<span class="pill">' + status + '</span>'"></div>

Concatenation is the readable option inside an attribute. Template literals work too, but the backticks compete with quoting rules in HTML, so most pages keep the expression simple and move anything longer into a function passed through the constructor data. 

const bitsy = new BitsyJS({
    data: {
        renderRow: (member) => "<b>" + member.name + "</b> " + member.role,
    },
});

null and undefined render nothing#

null and undefined become an empty string, so the element is emptied instead of showing the word null. Every other value is converted to a string by the browser, including 0 and false. 

<span b-js="missingValue">text before run</span>
<!-- after run(): the element has no content -->

<span b-js="0"></span>
<!-- renders as 0 -->

This is a real difference from text placeholders, which leave a missing value untouched. Choose the directive that matches the behaviour you want when the data is not there yet.

Signals are called for you#

If the result is a signal, b-js calls it before writing. Writing b-js="count" and b-js="count()" therefore produce the same output, and both re-run when the signal changes because the read happens inside the directive's effect. 

const count = signal(3);
const total = computed(() => count() * 12);

const bitsy = new BitsyJS({ data: { count, total } });
await bitsy.run();
<span b-js="count"></span>
<span b-js="total().toFixed(2)"></span>
<span b-js="Math.round(count() * 1.618)"></span>

A plain value renders once. A signal, a computed, or any expression that reads one keeps the element up to date until the effect is disposed. See Signals for the reactive model.

Which scope the expression sees#

b-js evaluates against global data, the nearest b-data element, and the row scope inside a loop. Local keys win, and a sibling scope is invisible.

b-js inside two scopes b-data

Both blocks read the same shared rawCount signal, and only the left scope resolves unit. The right scope reports undefined rather than throwing, which is how a missing key behaves inside a scope.

Generated markup is not scanned#

The generated HTML is inserted after the directives have already run, and nothing walks it again. A b-if, b-for, b-js or b-on attribute inside the string is inert, and a placeholder inside the string stays literal text.

Directive attributes are removed as they run, so an element that evaluated a b-js expression no longer carries that attribute and cannot be found by it. The panel at the end of the workbench above counts exactly that, and prints the literal placeholder from the generated markup. 

<!-- this writes a literal {rawCount()} into the page, it is not bound -->
<div b-js="'<span>{rawCount()}</span>'"></div>

If you need the generated markup to react, generate it from a function that reads signals and returns the finished string, or build the elements with placeholders in the page instead of in a string.

Use placeholders for plain text#

b-js owns the whole element: it replaces every child on each evaluation. Placeholders do the opposite job, inserting a value inside markup you keep, which is why they are the better tool for a name, a label or a single value in a sentence. 

<div b-data>
    <p>Hello {user.name}, you have {count} messages.</p>
</div>

<p>Total: <span b-js="cart.total().toFixed(2)"></span></p>

Do not put placeholders or directives inside a b-js element. The element's content is destroyed on the first evaluation, so a nested binding, an event listener or a child component is removed along with it. Keep b-js on a leaf element.

Trusted output only#

The expression is code, and the result is HTML. Both halves of that sentence are a security boundary: an expression can read browser globals, and a value containing a script tag or an event attribute is inserted as-is. 

<!-- never do this with input a visitor controls -->
<div b-js="userComment"></div>

Escape or sanitize anything untrusted before it reaches a binding, and prefer signal writes with fixed strings over concatenating user input into markup. The full trust model, including fragments and remote responses, is described in Security.
