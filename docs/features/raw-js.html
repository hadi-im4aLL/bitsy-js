Raw JavaScript

Use b-js to evaluate a JavaScript expression and replace an element's contents with the result as HTML.

An expression becomes HTML#

b-js evaluates its attribute as a JavaScript expression in the element's scope and assigns the result to the element's innerHTML. The attribute value is the whole expression. 

<span b-js="count * 2"></span>
<span b-js="price.toFixed(2)"></span>
<span b-js="new Date().toLocaleDateString()"></span>

Each evaluation replaces the element's contents. The browser converts results such as 0 and false to strings. A plain object renders as [object Object], so format it before returning it.

Use a placeholder such as {user.name} instead when you want to insert a value without replacing its surrounding markup.

Building HTML strings#

The result is written as markup, not text, so a string containing tags creates real elements. That is what makes list rows, badges and small tables possible from a single expression. 

<div b-js="'<strong>' + count + '</strong> rows ready'"></div>
<div b-js="'<span class="pill">' + status + '</span>'"></div>

Use concatenation or a template literal for short expressions. For longer markup, pass a rendering function in the constructor's data option and call it from b-js. 

const bitsy = new BitsyJS({
    data: {
        renderRow: (member) => "<b>" + member.name + "</b> " + member.role,
    },
});

null and undefined render nothing#

null and undefined become an empty string, so the element is emptied instead of showing the word null. Every other value is converted to a string by the browser, including 0 and false. 

<span b-js="missingValue">text before run</span>
<!-- after run(): the element has no content -->

<span b-js="0"></span>
<!-- renders as 0 -->

Unlike b-js, a text placeholder stays visible when its value is missing. If a b-js expression fails to evaluate, BitsyJS logs the error and renders false.

Signals are called for you#

If the result is a signal, b-js calls it before writing. Writing b-js="count" and b-js="count()" therefore produce the same output, and both re-run when the signal changes because the read happens inside the directive's effect. 

const count = signal(3);
const total = computed(() => count() * 12);

const bitsy = new BitsyJS({ data: { count, total } });
await bitsy.run();
<span b-js="count"></span>
<span b-js="total().toFixed(2)"></span>
<span b-js="Math.round(count() * 1.618)"></span>

A plain value renders once. A signal, a computed, or any expression that reads one keeps the element up to date until the effect is disposed. See Signals for the reactive model.

The buttons write to the signal. Only the bindings that read it directly or through the computed value update.

const count = signal(3);
const total = computed(() => count() * 12);

const bitsy = new BitsyJS({
    data: { count, total, rate: 12 },
});

await bitsy.run();
<!-- three shapes of output -->
<p b-js="total().toFixed(2)"></p>
<p b-js="count"></p>
<p b-js="Math.round(count() * 1.618)"></p>

<!-- a returned string becomes markup -->
<div b-js="'<strong>' + count() + '</strong> units at <em>$' + rate + '</em> each'"></div>

<!-- written after binding, so this placeholder stays text -->
<div b-js="'<span class="pill">{count()}</span> stays literal'"></div>

<button type="button" b-on:click="count.update(n => n + 1)">Add one</button>

After run(), the final panel counts remaining b-js attributes and shows that the generated placeholder stayed literal.

Which scope the expression sees#

b-js evaluates against global data, the nearest b-data element, and the row scope inside a loop. Local keys win, and a sibling scope is invisible.

b-js inside two scopes b-data

Both blocks read the same shared rawCount signal, and only the left scope resolves unit. The right scope reports undefined rather than throwing, which is how a missing key behaves inside a scope. 

<!-- count and appName come from the constructor data -->
<div b-data="{ label: 'left', unit: 'kg' }">
    <p b-js="label + ' scope: ' + count() + ' ' + unit"></p>
    <p b-js="'global app: ' + appName"></p>
</div>

<div b-data="{ label: 'right' }">
    <p b-js="label + ' scope: ' + count()"></p>
    <p b-js="'unit in this scope is ' + typeof unit"></p>
</div>

Generated placeholders stay literal#

b-js inserts HTML without binding placeholders or running directives on the new content itself. Event listeners are attached in a later pass during run(), so event attributes in the initial output can still be picked up. A later b-js update does not attach listeners to the replacement HTML.

BitsyJS removes the b-js attribute when it binds the expression. Use an ID or class to find that element afterwards.

<!-- this writes a literal {rawCount()} into the page, it is not bound -->
<div b-js="'<span>{rawCount()}</span>'"></div>

If you need the generated markup to react, generate it from a function that reads signals and returns the finished string, or build the elements with placeholders in the page instead of in a string.

Insert values with placeholders#

A placeholder inserts a value without replacing its surrounding markup. Use one for a name, a label or a value in a sentence. Placeholders can still render HTML; see Rendering HTML values. 

<div b-data>
    <p>Hello {user.name}, you have {count} messages.</p>
</div>

<p>Total: <span b-js="cart.total().toFixed(2)"></span></p>

Do not put placeholders or directives inside a b-js element. The element's content is destroyed on the first evaluation, so a nested binding, an event listener or a child component is removed along with it. Keep b-js on a leaf element.

Trusted output only#

Use only trusted expressions: they run as JavaScript and can access browser globals. BitsyJS assigns the result to innerHTML without escaping or sanitizing it. 

<!-- never do this with input a visitor controls -->
<div b-js="userComment"></div>

Escape untrusted text before inserting it into HTML, or sanitize untrusted markup before rendering it. See Security for the trust rules for bindings, fragments and remote responses.
