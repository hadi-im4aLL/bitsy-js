Forms

A form with data-b-form-ajax="true" submits with fetch. The response renders into a target element, and the form can show a loading state, ask for confirmation or remove itself.

AJAX submission#

A form with data-b-form-ajax="true" submits with fetch instead of navigating. The value must be exactly true; any other value leaves the form to the browser. The same form also needs a target, data-b-form-ajax-target, which is a CSS selector for the element that receives the response. 

<form action="../api/contact.json"
      method="get"
      data-b-form-ajax="true"
      data-b-form-ajax-target="#contact-result">
    <input class="form-input" type="text" name="name" />
    <button class="button button-primary" type="submit">Send</button>
</form>

<div id="contact-result" data-b-use-template="#contact-template"></div>

Without a target the handler warns in the console and returns before any request is made, so a misspelled selector looks like a broken button with no network activity at all. The submit event is cancelled as soon as the AJAX path is taken, which is what keeps the page in place.

Methods, URL and body#

The method comes from the form's method attribute and is limited to get, post, put, patch and delete. Anything else, including an empty attribute, falls back to get. 

<!-- GET: fields are appended to the action URL as a query string -->
<form action="/search" method="get" data-b-form-ajax="true" data-b-form-ajax-target="#results">

<!-- POST: fields are sent as the request body -->
<form action="/users" method="post" data-b-form-ajax="true" data-b-form-ajax-target="#result">

Fields are collected with new FormData(form), then converted to URLSearchParams. For get the parameters are appended to the action URL, keeping any query string the action already has; for every other method the same URLSearchParams object becomes the body. When the form has no action, the current page URL is used as the base.

Rendering the response#

The response goes through the same parser and the same renderer as remote data: JSON becomes an object, text/html and other text/* responses become a string, images become a Blob, and anything else is tried as JSON and kept as text when that fails. Without a template the target receives indented JSON or raw HTML. 

<template id="contact-template" data-b-remote-data="response">
    <p>Status: {response.status}</p>
    <p>{response.message}</p>
</template>

The template names its data with data-b-remote-data, exactly like a remote template, and the response is the value under that name. The same scope rules apply: only that key is available, and top-level placeholders are substituted once, so repeated submissions should rely on b-for and b-if for anything that changes.

Loading state, confirm and removal#

While the request runs, a class is added to the form and to its submit controls, and the submit controls are disabled. The default class is is--loading and data-b-form-indicator replaces it. A submission already in flight blocks a second one. 

<form action="/users"
      method="post"
      data-b-form-ajax="true"
      data-b-form-ajax-target="#user-list"
      data-b-form-indicator="is--loading"
      data-b-form-confirm="Create this user?"
      data-b-form-remove-on-submit="true">

data-b-form-confirm asks with window.confirm before the request, and cancel means no request. data-b-form-remove-on-submit="true" removes the form after a successful response, which suits a dialog or a one-shot creation form; it is skipped when the request fails, and it is read as a string so the value must be exactly true.

Validation runs first#

BitsyJS attaches one submit listener per form. When the form also has data-b-validate-form="true", the fields are validated before anything is sent: an invalid form cancels the submit event and stops there, and a valid form continues into the AJAX path. A single submit therefore either produces error classes and messages, or a request and a rendered response. 

<form action="/users"
      method="post"
      data-b-validate-form="true"
      data-b-form-ajax="true"
      data-b-form-ajax-target="#result">
    <div class="form-field">
        <label class="form-label" for="email">Email</label>
        <input class="form-input" id="email" name="email" data-b-validate="required|email" />
        <small class="form-text" data-b-validate-message="email"></small>
    </div>
</form>

The rules, the message slots and the class names are described on Validation.

Native forms still work#

A form without data-b-form-ajax and without data-b-validate-form is never touched: no listener is attached and the browser submits it as usual. A native form that only has data-b-validate-form="true" is validated first and then handed back to the browser with requestSubmit(), so an invalid attempt keeps the page and a valid one follows the normal submit path.

That makes the AJAX attributes an opt-in layer: the same markup can start as a plain server-rendered form and gain fetch, validation and template rendering without changing the fields.

What it does not do#

  • No file uploads. The body is URLSearchParams built from FormData, so a File value is converted to a string instead of being sent as a part.
  • No error UI. A rejected request is logged with console.error and nothing is rendered, while the indicator is still cleaned up.
  • No redirection, history or focus handling after the response. Whatever the template renders is the whole feedback.
  • Listeners are attached once during run(). A form inserted into the page later is not wired, and the data-b-form-* attributes stay in the DOM.
