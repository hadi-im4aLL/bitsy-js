A view layer for the HTML you render.

BitsyJS adds data binding, loops, conditions, fragments and signals to server-rendered markup, after the page loads. No template language, no compiler and no second copy of your HTML.

What it does

Small surface, real features.

Six directives and a signal layer cover the parts of a page that change.

b-data

Keep the markup you already have

Values read from the nearest scope. They render as HTML, and a missing key leaves the braces in place.

Template

<ul>
  <li b-for="player of players">
    {player.name} - {player.score}
  </li>
</ul>

Output

  • Alpha10
  • Beta7
  • Gamma5

b-for / b-if

Loops and conditions

Repeat real elements, hide them with display: none, and read loop metadata such as _index and _isLast.

b-for="player of players"

signal()

Signals when a value moves

Text, attributes, conditions and loops that read a signal update when it changes. Set a value, or derive the next one.

count.update(n => n + 1)

b-view

Fragments from your server

Fetch a partial and inline it. Nested fragments resolve relative to their parent, so the folder stays self-contained.

b-view src="./cart.html"

data-b-*

Events and forms

Bind any DOM event, validate on submit and post with fetch, without wiring listeners by hand.

data-b-validate="required|email"

The model

The model

Render once. Update only what changed.

BitsyJS is not a framework. It is one pass over the page you already served: read the attributes, bind the values, attach the events, then get out of the way.

  • {stat.value}{stat.label}

Reference

Every directive is markup you can read.

Most directives are ordinary HTML attributes; b-view and b-container are custom tags. BitsyJS removes or unwraps each one after it runs, so the markup the browser keeps is still plain HTML.

Nothing to hydrate. The server sends the real page. BitsyJS enriches it in place and leaves the document readable if the script never arrives.
Core directives and the scope each one reads
Directive What it does Reads from
b-data Creates a local scope for placeholders and nested directives. Nearest scope
b-for Repeats an element for each item and exposes loop metadata. Global and b-data
b-if Shows or hides an element with display: none. Scope and loop
b-view Custom tag. Fetches an HTML fragment and inlines it at the element. Surrounding scope
b-container Custom tag. Groups markup and removes its own wrapper after rendering. No scope
b-js Evaluates an expression and writes the result as HTML. Nearest scope
b-on:event Runs JavaScript in the current scope on any DOM event. Scope and $event
data-b-* Events, remote templates and form validation attributes. Document

Quick start

Three steps, no build step.

Add the module, describe the data, then call run().

01

Load the module

Import the browser build from npm or a CDN. It is a single ES module.

02

Describe the data

Pass values, signals and derived values in the constructor.

03

Run after load

Fragments load, bindings apply and events attach. Then the attributes are removed.

index.html 
<div b-data>
  <h2>{title}</h2>

  <ul>
    <li b-for="player of players">
      {player.name} - {player.score}
    </li>
  </ul>

  <button b-on:click="count.update(n => n + 1)">
    Count: <span b-js="count()">0</span>
  </button>
</div>
app.js 
import { BitsyJS, signal } from "./bitsy.min.js";

const count = signal(0);

const bitsy = new BitsyJS({
    data: {
        title: "Scoreboard",
        players: [
            { name: "Alpha", score: 10 },
            { name: "Beta", score: 7 },
        ],
        count,
    },
});

await bitsy.run();
